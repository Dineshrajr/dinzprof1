# SuperKart — Automated MLOps Sales Forecasting Pipeline

An end-to-end MLOps pipeline that predicts `Product_Store_Sales_Total` for
SuperKart, with automated data registration, preprocessing, model
training/tuning/evaluation, model registration, and deployment — wired
together with a GitHub Actions CI/CD workflow.

## How the pipeline fits together

1. **`src/data_prep.py`** loads the raw CSV, registers it on the Hugging
   Face dataset space, cleans it (fixes the stray `"reg"` sugar-content
   label, drops the non-predictive `Product_Id`/`Store_Id` identifier
   columns, engineers `Store_Age`), splits it 80/20 into train/test, saves
   both locally under `data/processed/`, and re-uploads them to the same
   dataset space.
2. **`src/train.py`** loads train/test back from the Hugging Face dataset
   space, one-hot encodes the categorical columns, and runs a
   `GridSearchCV` over Decision Tree, Bagging, Random Forest, AdaBoost,
   Gradient Boosting, and XGBoost regressors. The best model (by test
   RMSE) is saved locally and registered on the Hugging Face model hub.
3. **`deployment/hosting.py`** pushes `app.py`, the `Dockerfile`, and
   `requirements.txt` to a Hugging Face Space (Docker SDK), which builds
   and serves the Streamlit app. The app downloads the registered model
   from the model hub at startup and serves predictions.
4. **`.github/workflows/pipeline.yml`** automates all of the above on
   every push to `main` (and on demand), then commits the refreshed
   `metrics.json`/train-test split back to `main`.

## Running locally

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export HF_TOKEN=hf_xxx           # a Hugging Face token with write access
export HF_USERNAME=your-hf-username

python -m src.data_prep
python -m src.train
python -m deployment.hosting
```

Without `HF_TOKEN` set, `data_prep.py` and `train.py` still run fully
(clean data, split, train, tune, evaluate) using local files only — the
Hugging Face upload/registration steps are skipped with a log message,
which makes local development and testing possible without any external
account.

## CI/CD setup (one-time, in the GitHub repo settings)

Add these two **repository secrets** (*Settings → Secrets and variables →
Actions*):

| Secret | Value |
| --- | --- |
| `HF_TOKEN` | A Hugging Face access token with **write** permission |
| `HF_USERNAME` | Your Hugging Face username |

Once set, every push to `main` runs the full pipeline and deploys the
latest model to the Space automatically.
